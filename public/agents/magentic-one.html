Summary

Magentic-One is an open-source multi-agent system from Microsoft Research, released in November 2024 on the AutoGen framework, in which an orchestrator plans and directs agents that browse the web, read files, write code and run it in a terminal. Six independent studies that ran it were found (four peer-reviewed). On GAIA it solved about 38% of tasks with GPT-4o in one study and about 43% of Level 1 and 26% of Level 2 tasks with Qwen-Plus in another; on large document-processing workflows it did not complete tasks reliably. Security studies found that malicious files or web pages could redirect it to run attacker code in most trials (97% with GPT-4o and a local file), and that benign errors often led it to unsafe actions such as privilege changes. One study tested the current release (0.7.5). Since October 2026 the developer's AutoGen page says the project is archived and no longer receives bug or security fixes; GitHub does not mark the repository as archived. Scope

Magentic-One as released by Microsoft in AutoGen: the Magentic-One group chat with its Orchestrator, WebSurfer, FileSurfer, Coder and ComputerTerminal agents (autogen-agentchat and autogen-ext 0.4 to 0.7.5; 0.7.5 of 30 September 2025 is the latest release), the magentic-one-cli tool and the original November 2024 package, run with a language model chosen by the user. Magentic-UI, the Magentic orchestration in Microsoft Agent Framework and setups that keep only the orchestrator with other agents are separate and not counted here. AutoGen Studio is covered only as context under disputes. Results depend heavily on the language model, the configuration and the task.

How sources were counted

The Magentic-One technical report, the AutoGen repository and documentation, and Microsoft's own GAIA, AssistantBench and WebArena results are the developers' material and are not counted; GAIA leaderboard entries submitted by Microsoft are listed as other. Papers co-authored by AutoGen team members (Who&When, Who&When Pro) and studies with Microsoft-affiliated authors are excluded. Studies by independent authors that run Magentic-One with its own agents count, with competing methods disclosed. Setups that keep only the Magentic-One orchestrator with other agents, re-analyses of traces produced by others, and studies that only list earlier results are listed as other. Magentic-UI and the Magentic orchestration in Microsoft Agent Framework are separate products and are not counted.

Security and disputes

No CVE or GitHub security advisory was found for Magentic-One, autogen-agentchat, autogen-ext or magentic-one-cli in NVD or GitHub on 20 October 2026. Pull request #7463, merged on the main branch on 25 March 2026, restricted component loading to AutoGen namespaces and hardened the VideoSurfer agent against URL input and path traversal; it is not in any PyPI release (the latest, 0.7.5, is from 30 September 2025). On 16 October 2026 the developer updated the repository README to state that AutoGen "has been archived and is no longer actively maintained by Microsoft" and that Microsoft is not providing bug fixes or security fixes, and pointed users to Microsoft Agent Framework. GitHub did not mark the repository as archived (checked 20 October 2026). A security company lists an unconfirmed path-traversal report for magentic-one-cli as submitted to Microsoft, with no CVE or advisory. The AutoJack issue (June 2026) concerned the MCP WebSocket in AutoGen Studio, which is not part of Magentic-One, and Microsoft states it never shipped in a PyPI release. No legal or regulatory action was found.

Uncertainties

  • Results reflect the language model and Magentic-One together; studies used GPT-4o, Gemini 1.5, Qwen-Plus, GPT-5 and GPT-5.4 models.
  • Only one counted study states the version tested; the others most likely used 0.4.x releases from 2025.
  • Since 16 October 2026 the AutoGen README says the project is archived and no longer receives bug or security fixes, although GitHub does not mark the repository as archived (20 October 2026); later security issues may not be fixed, and the March 2026 hardening is not in a PyPI release.
  • Magentic-UI and the Microsoft Agent Framework Magentic orchestration are separate products; their results are not counted here.
  • Several studies run the Magentic-One orchestrator with substituted agents; they are listed as other, and counting them would change the grade (see Decision 0088, D2).
  • Studies with Microsoft-affiliated authors who are not on the Magentic-One team are excluded; counting them would change the grade (see Decision 0088, D3).
  • Two counted studies share authors (Multi-Agent Systems Execute Arbitrary Malicious Code and Agent Meltdowns).

Sources

Independent performance sources (counted)

  • Multi-Agent Systems Execute Arbitrary Malicious Code (Triedman, Jha, Shmatikov; Cornell Tech; COLM 2025): control-flow hijacking through malicious local files and web pages in AutoGen (default Magentic-One group chat with orchestrator, file surfer, web surfer, coder and code executor), CrewAI and MetaGPT; 'the Magentic-One orchestrator, running on GPT-4o, executes arbitrary malicious code 97% of the time if it interacts with a malicious local file', and 88% of the time with Gemini 1.5 Pro and a malicious web page. Shares authors with Agent Meltdowns (counted) — accessed 2026-10-20
  • Why Do Multi-Agent LLM Systems Fail? (MAST; UC Berkeley, Intesa Sanpaolo; NeurIPS 2025 Datasets and Benchmarks): 1,642 annotated traces from seven multi-agent systems, including 195 Magentic-One traces on GAIA with GPT-4o; Magentic-One succeeded on 38.0% and failed on 62.0% of the GAIA tasks run (Figure 5), with failures classified by the MAST taxonomy — accessed 2026-10-20
  • Seeing the Whole Elephant (TraceElephant; Institute of Software, Chinese Academy of Sciences; ACL 2026): the authors ran Magentic-One on GAIA (119 traces, 74 failed) and AssistantBench (30 traces, 17 failed) at temperature 0.3 to build a failure-attribution benchmark; agents that interact with external environments, such as web browsing, accounted for about half of failures. Task selection served the benchmark, so the failure share is not a benchmark score — accessed 2026-10-20
  • A Two-Tier Perspective on Inference-Time Parallelism in Multi-Agent LLM Systems (Beijing University of Posts and Telecommunications; ICML 2026, PMLR 306; preprint arXiv 2608.05791 counted once): Magentic-One with Qwen-Plus as the baseline on GAIA; the authors' parallel configurations raised accuracy 'from approximately 43% to 52–57% on Level 1 tasks, and from around 26% to up to 39% on Level 2 tasks', with Magentic-One taking about 320 s per Level 2 task against about 170–280 s. Authors propose a competing method built on the Magentic-One architecture (disclosed) — accessed 2026-10-20
  • Agent Meltdowns (Jha, Triedman, Bhattacharya, Shmatikov; Cornell University; preprint, May 2026): unsafe actions after benign errors (404, 429, missing files) in Magentic-One, OpenAI Codex, Claw Code and the HAL Generalist Agent; Magentic-One 'Version 0.7.5, accessed via AutoGen on PyPI on 2026-05-02', mainly with GPT-5. For medium- and high-severity behaviours with GPT-5, Magentic-One's planned-to-attempted rate was 90.9%, attempted-to-successful 58.6% and reporting rate 54.3%; it accounted for 45.5% of agent privilege escalations (30/66) and 76.9% of access-control mutations (10/13) across the four harnesses. Shares authors with Multi-Agent Systems Execute Arbitrary Malicious Code (counted) — accessed 2026-10-20
  • APWA (Northeastern University; preprint, May 2026): Magentic-One as a baseline for large document-processing workflows with GPT-5.4-family models; 'Magentic-One is unable to complete any of the tasks reliably, only managing to produce an output in a single trial for PII-300k with all 4096 documents'; the authors describe orchestration failures and a FileSurfer run that consumed over 6.5M input tokens before a 30-minute timeout. Authors propose a competing architecture (disclosed) — accessed 2026-10-20
