## 2. The convention (sources)
- llms.txt v2 proposal, Jeremy Howard, https://llmstxt.org/ (updated 2026-08-10): an H1, a blockquote summary, optional detail, and H2 "file lists"; the index should stay small and link to detail. It is "a proposal" open for community input — **not a standard**. It does **not** define llms-full.txt.
- llms-full.txt: a Mintlify convention "developed by Mintlify in collaboration with customer Anthropic" — https://www.mintlify.com/blog/what-is-llms-txt ; Mintlify docs https://www.mintlify.com/docs/ai/llmstxt (serves both files, advertises them with a `Link` header `rel="llms-full-txt"`). Overview: https://www.launchscaler.com/blog/llms-full-txt-vs-llms-txt ("a convention, not a spec"; per page: title, source URL, description, content). Examples of index + full export: https://www.mintlify.com/blog/real-llms-txt-examples (Anthropic docs).
- Crawler/agent support is uncertain: no search engine or AI crawler publicly commits to reading either file; the llmstxt.org page reports use mainly at inference time by agents that are pointed at it. Treat it as a convenience file, not a discovery channel.

## 3. What the rules say
Informational only; fixed disclaimer; no ranking/endorsement/certification language; no ratings markup (n/a for .txt); no JavaScript; CC BY 4.0 for data; numbers/dates must be generated, not typed; deploy needs separate approval.

## 4. Proposal: llms-full.txt
Generated by `build_data.py` (new `build_llms_full()`), from `agents/*.yaml` + the same values as agents.json, into `public/llms-full.txt`. Structure:
1. `# Agent Reputation & Trust Clearinghouse: full text for language models`
2. Blockquote = FEED_DISCLAIMER.
3. As-of line: latest last_reviewed, rules version, links to llms.txt and agents.json.
4. `## How this directory works`: HOW_CALLOUT verbatim + the four HOW_FULL subsections verbatim (these already state the threshold, weights and grade meaning; the full methodology stays on methodology.html).
5. `## How to quote these scores`: CITATION constant + the don'ts sentence + link to citing.html.
6. `## License`: LLMS_LICENSE.
7. `## Entries` (alphabetical, "the order carries no meaning"): per entry — name, entry URL, category/type, status, factor scores, overall + grade (or "none … no evidence grade"), grade note, counted / other source counts, last reviewed, scope, summary, uncertainties, sources (option A) and a per-entry disclaimer line with its as-of date.
8. `## Changes`: changelog + both feeds; closing disclaimer.

Size (current data): **option A, full source URLs: 131,226 bytes (~33k tokens)**; **option B, counts + pointer to agents.json: 88,975 bytes (~22k tokens)**. Proposed cap: 250 KB (warn at 200 KB).

## 6. Checks (check_export.py)
1. llms-full.txt exists and equals a fresh generation (no hand edits).
2. Every agents.json entry appears once (entry URL + heading); status, the four factor scores, overall, grade, grade note, counted count and last_reviewed match agents.json.
3. FEED_DISCLAIMER in the header blockquote and once per entry (entries + 2).
4. As-of date = max(last_reviewed) = agents.json dataset date.
5. Size: error > 250 KB, warning > 200 KB.
6. Banned-word scan on the generated framing text (headings, labels, header, How/Quote/License/Changes sections), as for compare pages. Entry summaries/uncertainties are excluded because they reproduce already-published entry text: the scan finds 11 uses there ("best" ×4 and "top" ×1 describing study results, e.g. "the best correct-and-secure score (35.8%) of three"; "verified" ×6 as "not independently verified" / "OSWorld-Verified"). These already appear on the entry pages; no rewording proposed.
7. llms.txt links to llms-full.txt; agents-data.html and citing.html list it.
8. Footer: every page (except FOOTER_SKIP) has the citing.html link (covered by footer equality + one explicit assertion).

## 7. Risks and mitigations
- Staleness → generated on every build; check 1/4.
- Size / context cost → option B or cap; llms.txt stays the small entry point.
- Quoting out of context / dropping disclaimers → disclaimer in header and per entry, as-of date per entry, quoting guidance at the top.
- Duplication with agents.json/pages → single source + check 2.
- Maintenance → one generator function, no typed text beyond existing constants.
- Banned words inside quoted study results → excluded from the scan by design, reported here for the record.
- Uncertain uptake → low cost; note it is a convenience file.

## 10. Plain-English terms
- **llms.txt / llms-full.txt:** plain-text files for AI tools; the first is a short map, the second puts everything in one file.
- **Convention, not standard:** a widely copied habit, with no official body or guarantee that tools read it.
- **Footer equality check:** a test that every page has exactly the same footer.
- **Token:** roughly 4 characters of text; AI tools have limits on how many they can read at once.
- **Generated:** written by the build script from the data, so it can't drift.
